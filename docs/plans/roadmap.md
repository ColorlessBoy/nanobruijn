# 教学系统路线图（待排期功能）

> 来源：2026-09-02 用户需求。状态：设计草案，未实施。

## 1. 做题过程记录 + 学习报告（持久化）

**现状**：REPL 已自动记录每次会话到 `py_nanobruijn/sessions/*.repl`（逐行输入，
gitignore，回放用），但没有面向玩家的"学习成果文件"。

**目标**：玩家做完（退出世界 / #quit / 通关）时获得一份**持久化的学习报告**，
做题过程与遇到的问题都有结构化记录。

**设计草案**：

- 数据源（已有/易采集）：
  - 每关的 tactic 序列（含错误尝试）、hint 使用、步数、星级（GameSession）
  - 卡点：报错信息（玩家看到的）+ 报错时的目标/上下文
  - 世界/关卡进入与退出时间戳
- 产出：`py_nanobruijn/reports/<时间戳>-<世界>.md`（人类可读学习报告）：
  - 通关概况（星级表、总步数 vs 标准解）
  - 每关过程回放（tactic 序列 + 错误尝试标注）
  - "你的卡点"小节（报错聚合：哪类错误最多、哪关用了 hint）
- 报告在退出 REPL 时提示路径："学习报告已生成：xxx.md"
- 隐私：本地文件，不自动上传；gitignore

**验收**：fresh 玩一遍 And 世界 → reports/ 出现可读报告；含星级、错误、hint 记录。

## 2. 问题上报系统（询问式反馈）

**现状**：报错只打印，玩家无处反馈"这条报错看不懂 / 这里有 bug"。

**目标**：玩家遇到问题时，REPL **主动询问**是否上报，一键落盘。

**设计草案**：

- 触发时机（两个都做）：
  - 游戏内：同一关卡连续 N 次报错（N=3，卡住信号）→ `是否上报这个问题？（y/n）`
  - 退出时：若本次会话有 error → 汇总询问一次
- 上报内容（`py_nanobruijn/feedback/<时间戳>.json`）：
  - 关卡（world/level/goal）、当时的上下文与目标、触发报错的输入、报错原文
  - 玩家可选留言（一行输入，可空）
- 上报后提示："反馈已保存到 xxx.json——可发给老师或附在 issue 里"
- 纯本地文件（无网络依赖，符合教学工具离线定位）；feedback/ 加入 .gitignore
- 与功能 1 联动：报告文件里附"待上报问题"小节

**验收**：故意连错 3 次 → 触发询问 → y 后 feedback/ 出现结构化 JSON；
退出时若有 error 汇总询问。
